## What dfe-infra Is

Multi-cloud Infrastructure-as-Code for deploying the full DFE 2.2 platform.
Terraform + Helm + ArgoCD. Replaces the AWS-specific `dfe-core` from 2.1.

**Repository:** `hyperi-io/dfe-infra`

## Two-Layer Architecture

### Layer 1: Base Infrastructure (Terraform + bootstrap.sh)

Cloud-specific provisioning. Varies per target.

| Component | Purpose |
|-----------|---------|
| K8s cluster | RKE2 / EKS / GKE / AKS |
| Envoy Gateway | Ingress + OIDC auth |
| cert-manager | TLS via ACME DNS-01 |
| External Secrets Operator | Secrets bridge (OpenBao / cloud SM) |
| ArgoCD + Valkey | GitOps orchestration |

### Layer 2: DFE Platform (ArgoCD ApplicationSets)

Identical deployment on ANY K8s. Cloud-agnostic.

| Component | Version | Purpose |
|-----------|---------|---------|
| Strimzi Kafka | 3.9.0 (KRaft) | Event streaming |
| ClickHouse | 24.8 (Altinity) | Analytics + observability |
| CNPG PostgreSQL | 17 | UI/HyperDX metadata |
| FerretDB | 1.24.0 | MongoDB wire protocol over PG17 |
| OTel Collector | 0.114.0 | Telemetry (DaemonSet + Gateway) |
| HyperDX | 1.7.0 | Observability UI |
| KEDA | 2.20.1 | Event-driven autoscaling (CPU default; scalo ScalingPressure opt-in via `dfe-keda-shim`) |
| DFE services | 2.2.0 | engine, UI, Rust pipeline apps |

### Deployment Flow

```text
Terraform (Layer 1) → bootstrap.sh → ArgoCD takes over
  Wave 2: operators (Envoy, KEDA, metrics-server)
  Wave 3: DNS/TLS addons
  Wave 4: data platform (Kafka, ClickHouse, PG, OTel)
  Wave 5: DFE services (engine, UI, receivers, loaders, transforms)
```

## Auth Architecture

```text
HTTPS → Envoy Gateway OIDC SecurityPolicy
         ├─ Authorization code flow
         ├─ Session cookie
         └─ Forward headers: X-Oidc-Subject, X-Oidc-Groups
              ↓
         dfe-engine
         ├─ OIDC header auth (production, Envoy-fronted)
         ├─ JWT Bearer auth (API clients, standalone)
         └─ LocalAuthProvider (dev/test fallback, bcrypt)
              ↓
         RBAC: group_role_mapping
         └─ OIDC groups → DFE roles (admin/operator/viewer)
              ↓
         ArgoCD RBAC (generated by dfe-engine)
         └─ generate_rbac_csv() → Helm values → ArgoCD ConfigMap
```

**Auth modes:**

- **Production:** Envoy Gateway OIDC SecurityPolicy (any provider: Entra, Google, Cognito, Keycloak)
- **Standalone/Docker:** JWT Bearer + LocalAuthProvider (still being designed)
- **Dev/Test:** auth disabled, root AuthContext

## Observability

**Stack:** OTel → ClickHouse → HyperDX (replaces Prometheus + Grafana)

Two-tier OTel Collector:

- **DaemonSet:** per-node kubelet/container metrics + logs
- **Gateway:** aggregation, batching, export to ClickHouse + HyperDX

## Helm Values Inheritance

```text
chart/values.yaml          → chart defaults
argocd/values/common.yaml  → global overrides (all clouds)
argocd/values/{cloud}.yaml → cloud-specific overrides
```

Cluster annotations bridge Terraform outputs → ArgoCD ApplicationSet templates.

## Relationship: dfe-infra ↔ dfe-engine

| Concern | dfe-infra | dfe-engine |
|---------|-----------|-----------|
| Config SSOT | Git IaC | YAML files (ConfigMap/volume) |
| Auth entry | Envoy Gateway OIDC | JWT + OIDC header + LocalAuth |
| RBAC policy | ArgoCD ConfigMap | `generate_rbac_csv()` |
| Secrets | Terraform + ESO | ENV vars + mounted secrets |
| Deployment | Helm chart in wave 5 | Deployed BY dfe-infra |
| Observability | OTel infrastructure | scalo logger auto-emit |
| Scaling | KEDA ScaledObjects (CPU default) | `dfe-keda-shim` (opt-in pressure/backlog metrics, fail-safe) |

**dfe-engine is deployed BY dfe-infra, not part of it.** dfe-engine manages
the DFE platform config and API; dfe-infra manages the infrastructure that
hosts it.

## Key Decisions (2.2 vs 2.1)

| Aspect | dfe-core 2.1 | dfe-infra 2.2 |
|--------|-------------|---------------|
| Clouds | AWS only | Rancher, AWS, GCP, Azure |
| Ingress | nginx + ALB | Envoy Gateway |
| Auth | Cognito + oauth2-proxy + Dex | Envoy OIDC SecurityPolicy |
| Cache | Redis | Valkey |
| Secrets | AWS SM | OpenBao / cloud SM + ESO |
| Observability | Prometheus + Grafana | OTel → ClickHouse → HyperDX |
| KEDA metrics | Prometheus scrape | CPU default; fail-safe `dfe-keda-shim` (opt-in pressure/backlog via OTel CH) |
| Kafka | AWS MSK | Strimzi (operator, multi-cloud) |
